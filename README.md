# 智能小援：部署包

状态：网站与接口代码已准备。尚未发布线上地址，尚未使用真实模型密钥验证生成。

## 1. GitHub Pages
在 Qinglin1233 账号创建仓库（建议 zhineng-xiaoyuan），上传本目录所有内容，包含 `.github/workflows/pages.yml`。
仓库 Settings → Pages → Source 选择 GitHub Actions，然后运行发布工作流。
工作流只发布 web 目录，server 不会进入网页包。预计地址为 https://qinglin1233.github.io/zhineng-xiaoyuan/，以 GitHub 实际发布结果为准。
也可以只上传 web 内文件到仓库根目录，并在 Pages 选择从 main 分支根目录发布。

## 2. 模型服务
模型账号和后端托管账号需自行注册。将 server 部署到支持 Node.js 22 的服务（或容器服务）。启动命令为 node server.mjs。
在托管平台私密环境变量中填写 .env.example 中的字段，MODEL_NAME 必须采用模型服务商当前可用标识；不得提交真实密钥到仓库。
ALLOWED_ORIGIN=https://qinglin1233.github.io（不含仓库路径）。
必须允许服务向模型API发起HTTPS请求。接口路径为 /api/generate，健康检查 /health。

## 3. 连接网站
在 web/config.js 将 apiUrl 改为部署成功的 https://服务地址/api/generate；此处只放接口地址，不放模型密钥。
也可使用网页“连接设置”填写接口地址。体验口令只在当前页面内存保存。

## 4. 使用与边界
教案：任意主题经模型生成，人工编辑后下载真正的 .docx 文件。
试卷：模型生成试卷与独立答案部分，目前共同导出一个Word，教师可删除答案部分形成学生卷。不是已有题库筛选系统。
作业：粘贴作答与评分量规生成批改建议；教师确认评语后，上传PDF或图片，点击原卷放置批注，导出完整PDF。不包含自动手写识别或自动题目定位。
数据：本机档案保存在浏览器。只有生成表单中的文本发送到模型；原卷在浏览器中处理。

## 5. 访问与费用控制
接口包含来源检查、单实例请求频率限制、每日请求总额度（默认100）和可选体验口令。来源检查不是身份认证。
usage.json 必须存储在持久化磁盘，实例数设为1；多实例/无持久磁盘环境必须改用共享计数服务再公开体验，否则重启或扩容可能重置额度。
不应依赖代理IP作为唯一限流标识；生产接入应在托管平台或网关额外配置访问限流与账单告警。
请求次数限制不是费用硬上限，请在模型平台配置可用的预算控制或有限余额。

## 6. 检查
Node.js 22+：在 server 目录运行 node --test test.mjs。
网站要通过HTTP预览（不直接双击HTML），因为PDF预览采用浏览器模块。
